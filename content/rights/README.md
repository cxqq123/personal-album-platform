# 图像版权清单

## 为什么是 CSV

- 你可以在 Excel / Numbers 里直接维护，不用写代码
- Git 能看 diff，谁改了哪一行一目了然
- CI 能校验，漏填直接卡住合并

## 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `status` | ✅ | `draft`（待核实）/ `ready`（可发布） |
| `id` | ✅ | 唯一标识，全小写，如 `qingming-shanghe` |
| `title_zh` | ✅ | 作品中文名 |
| `title_en` | | 英文名（Web 端 SEO 用） |
| `figure` | ✅ | 关联人物（朝代 · 姓名） |
| `museum` | ✅ | 现藏地 / 版权方 |
| `inventory_no` | | 馆藏编号 |
| `source_url` | ✅ | **能打开的作品页**（不是图片直链） |
| `license` | ✅ | 见下方枚举 |
| `license_url` | | 协议原文地址 |
| `commercial_ok` | ✅ | `yes` / `no` / `unknown` |
| `credit_line` | ✅ | 署名文案，会显示在作品页 |
| `checked_date` | ✅ | 核实日期 `YYYY-MM-DD` |
| `checked_by` | ✅ | 谁核实的 |
| `notes` | | 限制条件、待办 |

## 许可协议枚举与判定

| 值 | 含义 | 可商用 | 可上架 |
| --- | --- | --- | --- |
| `PD` | 公有领域（作者逝世逾版权期） | ✅ | ✅ |
| `CC0-1.0` | 放弃全部权利 | ✅ | ✅ |
| `CC-BY-4.0` | 署名即可 | ✅ | ✅（必须署名） |
| `CC-BY-SA-4.0` | 署名 + 相同方式共享 | ⚠️ | ✅（改编需同协议） |
| `CC-BY-NC-4.0` | 禁止商用 | ❌ | ❌ |
| `CC-BY-ND-4.0` | 禁止改编 | ⚠️ | ❌（裁切/缩放已被视为改编） |
| `ARR` | 保留所有权利 | ❌ | ❌ |
| `UNKNOWN` | 未核实 | ❌ | ❌ |

**规则：`commercial_ok=yes` 只允许搭配 PD / CC0 / CC-BY / CC-BY-SA。** 其他组合会被 CI 判为矛盾。

## 各馆速查（会变，以官网为准）

| 机构 | 通常条款 | 备注 |
| --- | --- | --- |
| 大都会艺术博物馆 | CC0（公有领域作品） | Open Access，放心用 |
| 盖蒂博物馆 | 开放内容计划 | 逐件确认 |
| 大英博物馆 | CC BY-NC-SA | **禁商用**，不能进一期 |
| 故宫博物院 | 条款限制多 | 需逐件确认，默认 `UNKNOWN` |
| 台北故宫 | 条款限制多 | 同上 |

> ⚠️ 古代画作本身是公有领域，**但博物馆拍摄的数字化照片可能另有权利**。这就是为什么清单记录的是"图像来源"而不是"作者"。

## 怎么加一条

1. 打开作品页，找到版权声明区（通常在页面底部）
2. 按上表判定 `license` 与 `commercial_ok`
3. 填入 CSV，`checked_date` 写今天
4. 提交 PR，CI 会校验格式与矛盾

## 三种状态

- **`ready` + `commercial_ok=yes`**：可进正式内容
- **`draft`**：允许存在（便于登记在研作品），但**不得被任何一期引用**，发布构建会失败
- **`UNKNOWN`**：默认按 `no` 对待，`ready` 状态下直接判为错误

## CI 门禁

- 每次 PR：校验格式、枚举、URL、矛盾组合
- 发布构建：`--strict` 模式，任何一行不是 `yes` 就失败

```bash
python3 tools/check_rights.py            # 日常校验
python3 tools/check_rights.py --strict   # 发布前
```
